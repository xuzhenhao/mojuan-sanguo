# 营地（REST）规则规格（H5 首版 · 对应 #90）

来源：PRD §10.6（V0.5.5 已扩写）、§8.5–8.6、§16.2.1。开发落地以本文 + PRD 为准。

## 1. 入口与出口
- 地图节点类型 `REST`（含第 8 层固定营地）→ 页面 P4b。
- 每进一次只做 **一项**；完成后或点「离开」→ 回地图 P3。
- H5：疗伤 / 淬炼 / 焚稿三项都开放。微信：默认疗伤+淬炼，广告解锁焚稿（见 PRD 16.2.1）。

## 2. 疗伤
```
heal = max(2, floor(maxHp * 0.3)) + relicBonus
hp = min(maxHp, hp + heal)
```
- 例：maxHp=8 → 基础 2；R03 青囊书 relicBonus=+2 → 共 4。
- 体力已满：选项置灰。

## 3. 淬炼
流程：选牌 → 生成 1 条 N/R 词条 → 确认 → 回营地结算页 → 回地图。

### 3.1 词条池
按牌的 category 读 `config/affixes/<cat>/`，只取 `rarity ∈ {N, R}`：

| category | N/R 可用（当前 config） |
|---|---|
| sha | E_S01 锋锐(R)、E_S02 轻招(N)、E_S03 追击(R)、E_S04 穿杨(N)、E_S05 烈焰(R)、E_S07 破甲(R) |
| shan | E_D01 余韵(N)、E_D02 反震(R) |
| tao | E_P01 厚味(N)、E_P02 回春(R) |
| trick | E_T01 精研(N)、E_T02 余墨(N)、E_T04 扩写(R) |
| equip | E_W01 坚固(N)、E_W02 贯虹(R) |
| jiu | （当前无 N/R，只有 E_P03 E）→ 酒类牌淬炼选项等价于「暂无可用词条」 |

> **词条表以 config 为准（V0.5.8 总策划拍板）**：上表按 `config/affixes/` 实际文件列出；旧版写的 E_T03 难消在 config 中不存在，已删除。以后词条增删以 config 为唯一来源，本表随之同步。

### 3.2 过滤（按序）
1. 该牌实例已有 2 条词条 → **不置灰、可正常选**，不直接追加：确认弹窗列出该牌现有的 2 条词条，玩家选其中一条替换为新词条，或选「放弃」。**选「放弃」也算本次营地已行动**（防止反复进出营地刷词条），之后疗伤 / 淬炼 / 焚稿都置灰，只能点「离开」。
2. 与已有词条 `mutex` / `mutexTags` 冲突 → 排除。当前 config 里只有一组互斥：E_S05 烈焰（`mutex: fire`）与火杀（已是火属性的杀不出烈焰）；其余词条没有 `mutex` / `mutexTags`。
3. E_S01：牌组中带锋锐的杀 ≥2 → 候选不含 E_S01。
4. 与牌效果无意义重复（配置侧）→ 排除。
5. 池空（经互斥 / 上限过滤后没有任何可用词条）→ 该牌在选牌网格中置灰，显示「此牌暂无可用词条」。**只有这种牌置灰**。

### 3.3 生成
- 过滤后池内 **均匀随机 1 条**（局内 rng，可复现）。
- **不做三选一**（有别于战斗内灵光一闪）。
- 不占战斗内灵光次数与保底。

### 3.4 淬炼界面（UI 定稿）
- **选牌**：与焚稿共用同一套选牌网格；顶部标题「淬炼·择一」。已有 2 条词条的牌**不置灰**，可点，角标「可替换」；只有「此牌暂无可用词条」的牌置灰（见 3.2 第 5 条）。
- **确认弹窗**：上方牌面预览，下方列新词条名与效果；按钮「淬炼」（primary）/「再想想」（secondary）；走引擎全屏 scrim。
  - 该牌已有 2 条词条时：弹窗另列出现有 2 条词条，玩家选一条被替换后点「淬炼」；或点「放弃」——放弃算本次营地已行动，回营地页后只剩「离开」。
- **结果面板**：牌上浮 + 金光入卷动效（时序同奖励页「收入」），一行「已淬炼：xx」，点任意处关闭 → 回营地页；此时其余三项置灰，只能点「离开」。
- 圆章图标、营火暂用代码绘制占位，出稿后替换。

### 3.5 无可淬炼牌
整副牌组过滤后都池空（每张牌都是「此牌暂无可用词条」，例如只有酒）→ 淬炼选项置灰。

## 4. 焚稿
- 删 1 张；删后约束：牌组 ≥8，且 ≥1 张杀类。
- 杀类判定：`category == sha`（含各类杀）。
- 不满足约束的牌置灰；整组无可删 → 焚稿置灰。
- 无撤销、不退铜钱（营地焚稿免费；集市删牌另计）。

## 5. 第 8 层固定营地
- 规则与随机营地完全相同。
- 生成约束：与第 8 层相连的第 7 层节点不能是 REST（PRD 10.4 noConsecutive）。

## 6. 埋点
- `rest_enter`（是否第 8 层）
- `rest_choose`（heal / temper / burn / leave）
- `rest_temper`（cardId, affixId）
- `rest_burn`（cardId）
