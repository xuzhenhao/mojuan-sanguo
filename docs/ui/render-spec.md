# 战斗页 Canvas 渲染规格（基于 v2 方案 A/B）

> 面向自研 Canvas 渲染器（H5 + 微信小游戏）。设计基准为 **390×844 逻辑像素（dp）**，渲染缓冲 = 逻辑尺寸 × `devicePixelRatio`（上限 3）。参考稿：`docs/ui/battle-mockups-v2/`。A=墨卷长轴，B=金漆屏风；有差异的地方会注明。

### 1.2 全屏与安全区
- 设计稿按 390×844 制作。实际屏幕用 **等宽缩放**：`scale = screenW / 390`，竖向多出或缺少的高度由**战场区（背景+敌人）弹性吸收**，顶部条和底部手牌区按安全区锚定。
- 安全区：小游戏用 `wx.getWindowInfo().safeArea`，H5 用 `env(safe-area-inset-*)` 读入后传给 Canvas。
  - 顶部条：`top = safeArea.top + 10`；小游戏右上角胶囊用 `wx.getMenuButtonBoundingClientRect()` 避让，**设置按钮要放在胶囊左侧**或改进左上菜单。
  - 底部：手牌与底栏锚定在 `safeArea.bottom`，底栏背景向下延伸到物理屏底（不能留黑边）。
- 背景层**按 cover 方式铺满物理屏**（含安全区外），其它层只放在安全区内。
- 超长屏（>2.1:1）：敌人行间距最多 +24dp，多余高度给远山背景；短屏（<1.9:1，如 iPhone SE）：后排敌人缩到 .66，我方立绘上移并裁切下半身（A），B 的判定区并入 Boss 牌右侧。
- 横屏不支持，锁定竖屏。

## 2. 交互
| 操作 | 行为 | 判定细节 |
|---|---|---|
| 点按卡牌 | 选中：上浮 22–26dp、放大 1.08–1.12，合法目标高亮（A 剪影朱砂描边光，B 牌框金光），非法目标 α.35 | 再点同一张取消；点空白取消 |
| 点选目标 | 选中卡后点合法敌人即出牌；点非法目标时卡牌抖动（±4dp，160ms） | 点击热区=剪影或牌框外扩 8dp |
| 拖拽出牌 | 按下移动 >8dp 进入拖拽：卡牌跟手（插值 0.35），从卡牌顶部到手指画墨线箭头（贝塞尔、末端箭头）；悬停在合法目标上时目标放大 1.05 并吸附箭头 | 拖回手牌区（y > 手牌区顶部-20）就取消；无目标牌（如藤甲、桃）拖过“出牌线”（手牌区顶部上方 60dp）即生效 |
| 长按（≥420ms） | 弹出详情：卡牌显示名称/费用/花色/一行描述/墨强化提示；意图显示行动预告；敌人显示状态列表；我方显示技能 | 长按时有环形进度反馈（0–420ms）；松手不触发出牌；点任意处关闭 |
| 军令不足 | 卡牌费用数字抖动 + 砚台（A）/虎符（B）闪红 | 不进入选中态 |
| 结束回合 | 单击；设置里“结束回合确认”打开时需二次点按（按钮变“确定？”1.5s） | 有未用军令时按钮呼吸提示（可关） |
| 响应窗口 | 弹出后只有合法牌和“承受”可交互；点合法牌即打出（无需目标）；倒计时（5/8/12s，设置可调）结束自动承受 | “自动出闪”打开时：仅 1 张合法牌就自动打出，并显示 0.6s 提示 |
| 副将技能 | 点副将圆章（A）/副将牌（B）发动，就绪时金色呼吸光 | 长按看技能说明 |
| 手牌滑动 | 手牌 >7 张时，A 压缩扇角，B 允许横向拖动滚动 | 滑动和拖拽出牌用初始方向区分：水平是滚动，向上是出牌 |
| 多点触控 | 只认第一指 | — |

## 4. 字体、文字样式与美术资源

### 4.1 字体
| 用途 | 字体 | 字号(dp) | 样式 |
|---|---|---|---|
| 书法名（卡名/武将名/按钮） | 马善政楷书 Ma Shan Zheng（OFL），**按用到的字做子集** | 卡名 20–22，武将名 26–30，按钮 21–22 | A 焦墨色 #1A1A1A；B 卡面焦墨、按钮宣纸白配 0 2 2 阴影 |
| 数字（费用/意图/血量/军令） | Georgia Bold 风格衬线数字，**做成位图字体** | 意图 17–23，军令 30–34，血条 9–11，费用 13–15 | 白字加 2px 黑色描边或阴影；致命意图用白字 |
| 说明文字（仅详情浮层） | 系统无衬线（PingFang / 思源黑体），不打包 | 13，行高 1.5 | 正文 #1A1A1A（A）/#F3EBD8（B） |
- 书法字体：小游戏用 `wx.loadFont` 加载子集 TTF；H5 用 FontFace。**常用名称（卡名/武将名/按钮）建议预渲染进图集**，避免首帧字体闪烁。
- 子集估算：战斗相关约 300 字，体积约 60–90KB；本 PR 的 demo 子集为 30KB woff。
- 色弱：花色同时用形状和红/黑字区分，B 的花色文字带阴影。设置“高对比手牌”时，花色角标改为黑底白字/红底白字。

| 牌框 | 4 类×2 方向 | 148×216，九宫格 | PNG | A 墨漆框，B 鎏金框，按类型分色 |

| 位图数字 | 2 套（白描边/金） | 每字 28×40 | 图集 | 0–9、+−×/ |

**图集**：按使用场景打包，单张 ≤ 2048×2048（小游戏兼容）。
- `battle_ui.atlas`：牌框、图标、徽章、数字、按钮，约 1 张 2048。
- `battle_fx.atlas`：特效贴图，1 张 1024。
- `cards_art_{n}.atlas`：卡牌插画，40 张分 2 张 1024。
- 立绘和敌人按章节动态加载，不常驻。

**体积估算（压缩后）**：UI 图集约 350KB，特效约 120KB，卡牌插画约 600KB，武将约 8×60KB=480KB，敌人约 20×25KB=500KB，背景约 3×2×120KB=720KB，字体约 80KB，合计 **约 2.8MB**。首包只放 UI、特效、字体和第一章资源（约 1.2MB），其余分包或放 CDN。

## 5. 重绘与缓存
| 区域 | 策略 |
|---|---|
| 背景（含纸纹、远山） | 预渲染到离屏 Canvas（物理分辨率），每帧整张 drawImage；只在切换章节或改变尺寸时重建。A 的 SVG 滤镜效果（晕染、纸纹）**全部烘焙成贴图**，运行时不做噪声计算 |
| 环境动效 | 独立小图层，低画质关闭；30fps 刷新 |
| 敌人（剪影+牌框+名字） | 每个敌人烘焙成一张离屏位图；受击闪白/溶解用 globalCompositeOperation 叠加，不重烘 |
| 敌人附件（意图/血条/倒计时） | 数值变化时重烘对应徽章的小位图（脏标记），每帧只贴图 |
| 我方立绘/武将牌 | 烘焙缓存；体力、护甲徽章单独缓存，变化时重烘 |
| 手牌 | **每张卡烘焙一张位图**（牌框+插画+书法名+费用+花色+墨角标）；状态变化（费用变化、强化、可用/不可用）时重烘。每帧只做变换贴图。流光用叠加层绘制，不重烘 |
| 底栏/顶栏 | 烘焙；数字变化时局部重绘 |
| 遮罩/响应 UI/飘字/粒子 | 每帧绘制（量小） |
| 详情浮层 | 打开时烘焙一次 |

- **主循环**：静止状态（没有动画也没有拖拽）时降到 0fps 或 10fps 待机，只保留循环动效（致命脉冲、墨角标呼吸、倒计时）所需的刷新；有动画时 60fps。
- **脏矩形**：可选。在每张卡/徽章已缓存的前提下，整屏重绘 390×844×dpr 在中端机上开销可接受，**先实现整屏贴图合成**，性能不足时再给背景以上的层加脏矩形。
- **离屏缓存上限**：卡牌 10 张、敌人 6 个、徽章约 30 个，约 12MB 显存（dpr=2），切换战斗时释放。
- **A 与 B 的差异**：A 的立绘大、背景层次多，背景缓存可以分 2 层做视差；B 的牌框多，九宫格牌框要先烘进每个敌人/卡牌的缓存，避免每帧做九宫格拼接。
