- **书法字体**：定稿为 **霞鹜文楷 LXGW WenKai**（OFL 1.1，[lxgw/LxgwWenKai](https://github.com/lxgw/LxgwWenKai)）。不补字、不换系统楷体回退；旧马善政（Ma Shan Zheng / `brush.woff`）方案废弃。
- **书法子集必须由构建脚本生成，禁止手工维护或复用 mockup 的字体文件**：
  - 字表来源是 `src/data/generated/config.json` 中**全部** `name`/`title` 字段（武将、技能、珠联、卡牌、词条、敌人、关卡），加上 `src/game` 里的书法 UI 文案常量（按钮、标题、印字等）。
  - 构建时对照源 TTF（霞鹜文楷）检查，**缺字直接报错**（禁止系统字体回退）。
  - 实测字表与包体（`/workspace/fonts` 子集）：**core 242 字 / 约 57KB woff2**（首包）；**完整子集 682 字 / 约 149KB woff2**。
  - 历史勘误：PR #68 复用 `mockups/v3/fonts/brush.woff` 时写过「缺 154 字 / 傕虓交美术补字」。实际所需是上述 242 / 682；旧马善政源字体**仅缺「傕」「虓」二字**（李傕郭汜、虓烈）。项目负责人已定**不补字**，改为霞鹜文楷（二字均有字形）。
  - 分两包：
    - `wenkai-core`：首屏 UI 文案 + 8 将名 + 技能名 + 第 1 章卡/敌人（242 字，约 57KB），进首包；
    - `wenkai-ext`：其余字（凑齐 682），进分包，在进入地图前异步加载完成。

## 3. 组件规格

### 3.1 金框（GoldFrame）—— 所有“牌”的外壳
- 外框 padding 4（小牌 3），圆角 4；材质为 5 段斜向金属渐变 `gold-hi → gold-lo → gold → gold-dk → #D6B065`；投影 `0 8 16 rgba(0,0,0,.7)`。
- 内窗：径向渐变 `#F6ECD2 → paper-3 → #7E6C4C`，内描边 1px `#2A1A08`，内阴影 16px。
- 变体：`gold`（主将/敌人/卡 E）、`silver`（副将/卡 R）、`bronze`（卡 N）、`jade`（卡 L，外发光 18px）。
- **九宫格**：角 12px 不拉伸；导出 148×216@2x 的 4 种材质。

### 3.2 卡牌（Card）
| 尺寸 | 用途 |
|---|---|
| 72×104 | 战斗手牌、兵书 |
| 104×150 | 奖励/集市大牌 |
| 36×52 | 兵书缩略 |
- 结构：费用珠（左上 22⌀ 玉色，大牌 28⌀）→ 花色点数（费用珠下方，竖排）→ 插画窗（类型底色：攻=朱砂、防=青、回=玉、锦囊=赭）→ 卡名（底部书法）→ 稀有度菱形（右上 10–12）→ 墨角标（左下菱形 26，金描边 + 发光）。
- **花色与点数放左侧**，因为手牌叠放时右侧会被遮住。
- 状态（发光均为烘焙的发光环贴图加 tint，见 §10）：`normal` / `selected`（上浮 22、放大 1.08、金色外发光）/ `legal`（响应时：金色外圈 2px + 光 20px）/ `illegal`（亮度 .3、饱和 .2）/ `unaffordable`（费用珠变红，点按时抖动）/ `ink-ready`（流光扫过，2.4s 循环）。

### 3.4 勾玉体力（JadeBeads）
- 珠径：主将 17，敌人和小牌 11，地图 HUD 12；间距 2–4。
- 满：径向渐变 `#D6F0E0 → jade → jade-dk`；空：`#777 → #2A2A2A`。
- 每行最多 9 颗；超过 9 时改为 1 颗珠加“×N”数字。**Boss 或体力 >10 的敌人改用血条**：10–13 高，朱砂渐变，加金色细描边和居中数字。

### 3.5 虎符军令（TallyEnergy）
- 3 枚虎符，每枚 30×42，竖向排列，间距 4，金渐变加投影；空的为 `#3A3027`。右侧是“3/3”数字（34 / 15）。
- 军令上限超过 3 时追加虎符，最多 5 枚，超过后只显示数字。消耗时自上而下熄灭；军令不足时整列红闪。

### 3.6 敌人牌、意图与行动倒计时
- 敌人牌：前排 96×132，Boss 116×160（上移 22），后排 76×104（亮度 .72）。前排间距 18，后排间距 120。

- **行动倒计时圈**（左上外挂 30⌀）：黑珠加金描边，上方有一段金弧，弧的角度对应进度；数字为距离行动的次数。等于 1 时外圈变朱砂。

### 3.8 按钮（Button）
| 类型 | 底 | 尺寸 | 用途 |
|---|---|---|---|
| primary | 朱砂渐变 `#C4513E→#7D2418` | 高 44（sm 32），宽 ≥ 96 | 出征、结束回合、抄录、离开 |
| confirm | 玉渐变 | 同上 | 确定、收入 |
| secondary | 褐渐变 `#5A4A3A→#2A1F16` | 同上 | 略过、跳过、刷新 |

### 3.9 横幅、面板与弹层
- **面板（Panel）**：竖向渐变 `rgba(42,20,16,.92)→rgba(15,7,5,.95)`，描边同按钮的 3 层，圆角 3。用于 HUD、属性条、抄录区。
- **提示横幅（Banner）**：横向两端渐隐的深漆条，上下各 1px gold-lo，内容为“图标 34 + 书法动词 26 + 数值”，例如“[闪] 出闪 ⚔6”。
- **进度条**：180×6，金→朱砂渐变；最后 2s 变红并抖动。
- **响应弹层**：全屏遮罩 `rgba(5,2,1,.72)`。攻击者、我方武将牌、合法手牌、底栏提到遮罩之上。弧形红箭从攻击者指向我方。横幅和进度条放在主将牌左侧，确定/承受（❤−N）按钮在横幅下方。
- **长按详情（Tooltip）**：宽 180，深漆底加金描边，内含标题（书法 24）+ 费用 + 花色 + 1–2 行 body。对齐到手指上方，并钳制在安全区内。
- **大印（Seal-XL）**：110×110，旋转 -6°，3 层描边，外加 40px 朱砂光，背后是旋转的金色放射光（遮罩成圆形）。

## 4. 页面布局摘要（dp）

### 4.0 视口适配（#111）
- 统一**等比缩放**，不做网格自适应。设计坐标固定 390×844，场景内拿到的 `width/height` 恒为 390×844，禁止各页自行算偏移/缩放（如 `(w-390)/2`、`h-844`）。
- `s = min(W/390, H/844)`，W/H 取 `visualViewport` 宽高减 `env(safe-area-inset-*)`；内容层居中。
- 余量不留黑边：宣纸底纹层用真实 W×H 单独绘制（cover），不进场景。
- canvas 像素尺寸 `W·dpr × H·dpr`，绘制乘 `s·dpr`；触摸反变换 `(x-offsetX)/s`、`(y-offsetY)/s`。
- resize / `visualViewport` resize / 横竖屏切换时重算并重绘；横屏与桌面同规则。
- 验收尺寸：360×640、375×667、390×844、412×915、465 宽（带地址栏）、768×1024。任何尺寸下卡牌第 4 列、右上计数、底部按钮完整可见且热区对齐。矮屏/窄屏（如 360×640，s≈0.76；320 宽同理）按钮视觉高度会低于 44px（约 33px），**视觉上接受**；但热区须在屏幕坐标下补足到不小于 44×44 CSS px（按钮矩形向外均匀扩展，不改绘制），相邻按钮热区不重叠。

## 6. 安全区与适配
- **缩放**：`scale = screenW / 390`（等宽）；竖向多出的高度分给“弹性区”：战斗是敌人区，地图是卷轴，其余页面是中部内容区。
- **安全区**：小游戏用 `wx.getWindowInfo().safeArea`，H5 用 `env(safe-area-inset-*)`。顶条 `top = safeArea.top + 10`；底栏底部 padding = `max(14, safeArea.bottomInset)`，底栏背景要延伸到物理屏底。
- **微信胶囊**：由 `wx.getMenuButtonBoundingClientRect()` 得到 `rect`（约 87×32，距右 7）。**右上 `rect.left - 8` 以右、`rect.bottom + 6` 以上的区域禁止放交互元素**。设置、铜钱等放在胶囊左侧或下方的 HUD 里。稿件中虚线框标出的就是胶囊位置。
- **调试状态条（只在调试版出现）**：显示 WebGL / dpr / 纹理用量 / 页面名，**正式版不绘制**（`MODE !== 'debug'` 且无 `?hud=1` 时不压入弹层）。
  - 位置固定在 `safeArea.top` 到 `+10` 的 10dp 窄条（顶条从 +10 开始，二者不重叠），x 从 12 起左对齐。
  - 9 号系统字，`rgba(244,220,154,.55)`，不接收手势。
  - 禁止放在底栏或任何按钮上（PR #68 中它压住了齿轮和出征）。参考稿：`v3/select.html#hud`。
- **长屏（>2.1:1，如 19.5:9 以上）**：战斗中前后排间距最多 +24，判定区下移，多余高度给背景远山；地图卷轴变长、少滚动；奖励和结算的内容整体垂直居中。
- **短屏（<1.9:1，如 iPhone SE 16:9）**：
  - 战斗：后排牌缩到 64×88，判定区并入 Boss 牌右侧（迷你 36×50），武将牌缩到 120×164。
  - 选将：网格改为 2 行 × 4 列，每格 72×100；技能印直径缩到 40。
  - 集市：货架间距压缩 20%。
  - 结算：立绘裁到胸部以上。
- 只支持竖屏。字体不缩放，最小字号 9（血条数字）。

## 7. 战斗页 Canvas 渲染要求
### 7.1 层级（z 从低到高）
0 背景（漆面 + 回纹 + 金山影 + 边框，静态）→ 1 环境（金尘）→ 2 后排敌人牌 → 3 前排敌人牌 → 4 敌人附件（意图/倒计时/勾玉/盾）→ 5 判定区 → 6 副将牌 → 7 主将牌 + 虎符 → 8 底栏 → 9 手牌 → 10 遮罩 → 11 焦点层（提升的攻击者/武将/合法牌）→ 12 响应 UI（箭头/横幅/进度/按钮）→ 13 飘字/粒子 → 14 详情浮层 → 15 系统（Toast/引导）。

### 7.2 交互
- 点牌后选中（合法目标亮金框，非法目标透明度 .35）→ 点目标出牌。
- 拖拽：移动 >8dp 开始；卡牌插值 0.35 跟手，并画墨线箭头吸附目标。拖回手牌区（y > 手牌区顶部 - 20）取消；无目标牌拖过出牌线（手牌区顶部上方 60）即生效。
- 长按 420ms（带环形进度）弹详情，适用于卡牌、敌人、意图、倒计时、副将技能。
- 手牌超过 7 张时可横向滚动：水平移动是滚动，向上移动是出牌。
- 响应窗口期间只有合法牌和确定/承受可交互；超时自动承受；“自动出闪”打开且只有 1 张合法牌时自动打出。
- 结束回合可选二次确认；副将牌点按发动技能。
- 只认第一指。

### 7.3 缓存
- 背景：离屏整张缓存。
- 每张手牌：烘焙为一张位图（金框九宫格 + 插画 + 书法名 + 费用 + 花色 + 墨角标），状态变化时重烘；流光作为叠加层另画。
- 每个敌人牌：主体烘焙；附件徽章单独缓存，数值变化时打脏标记。
- 武将牌：同上。
- 底栏和顶条：烘焙。
- 遮罩、箭头、飘字、粒子：每帧绘制。
- 静止时降到 10fps 待机，有动画时 60fps。离屏缓存上限约 12MB（dpr 2），退出战斗时释放。

## 8. 外围页面 Canvas 渲染要求
通用：背景（漆面+回纹+边框）全局共享**一张缓存**；顶条、底栏也做成共享组件缓存；页面切换用墨色横扫转场（450ms）。按钮按下的反馈在组件内部局部重绘。

### 8.1 选将

- **交互**：
  - 点网格：若主将为空，设为主将；否则设为副将。再点主或副可以取消。点“⇄”交换主副。不能主副同一人，选中时有抖动提示。
  - 长按网格武将或技能印，弹出技能详情。
  - **珠联提示（ComboChip）**：
    - 与技能印**同一行**（362–408），放在副将技能印右侧 12dp，竖直居中（y 373–397），高 24，圆角 12。
    - 底为面板渐变，加 1px `gold-mid` 描边 + 1px `lac-3`。左侧是 18⌀ 玉色“珠”印，后接书法 15 号 gold 字「珠联·名称」，不换行。

    - 只在主→副方向命中 config 且 `enabled !== false` 时显示；出现时淡入 200ms，同时主副两槽各闪一次玉色描边（300ms，烘焙发光环 + tint）。

  - 点兵书“+”打开兵书选择（0–2 张，天命 ≥3 时可选 3 张，只能选当前主/副可用的牌）。
  - 点天命印弹出天命 0–10 的滑动选择。
- **VFX**：选中时武将牌飞入槽位（300ms，back），盖印（150ms）；槽位外发光呼吸；“出征”按钮在主副都选定后才激活（attention）。

### 8.2 地图
- **层级**：背景 → HUD 面板 → 卷轴（纸底 → 远山晕染 → 路径层 → 节点层 → Boss 牌）→ 卷轴上下金轴（盖在内容上方）→ 底栏 → 节点详情浮层。
- **缓存**：卷轴内容（纸底 + 远山 + 全部路径 + 节点图标）**烘焙成一张长图**（宽 354，高为层数 × 62 + 头尾），滚动时只做 drawImage 裁剪。节点状态（已走变灰、当前头像）在烘焙时一并写入；可走节点的脉冲光是每帧叠加层（只有 1–4 个）。走完一步后重烘一次。
- **交互**：纵向拖动滚动卷轴（惯性，两端回弹）；进入时自动滚到当前层。点可走节点后头像沿路径移动（500ms）再进入节点；点不可走节点只弹出类型详情。长按节点看说明；HUD 上的宝物、丹药长按看说明，点丹药可使用。
- **VFX**：可走节点金色脉冲；走过的路径朱砂墨线**逐段描绘**（描边长度动画 400ms）；Boss 牌常驻淡红光；新章节进入时卷轴从上往下展开（800ms，可跳过）。

### 8.3 奖励
- **层级**：背景 → 放射光（旋转）→ 大印“胜” → 战利品胶囊 → 标题 → 3 张大牌 + 词条珠 → 宝物条 → 底栏。
- **缓存**：3 张大牌和宝物条各烘焙一次；放射光是单独一张贴图，每帧旋转绘制（或用 30fps 低频刷新）；大印静态缓存。
- **交互**：点卡牌选中（上浮加金光），再点“收入”确认（选中后双击也可直接收入）；长按看卡牌或词条详情；点宝物条领取宝物（与卡牌独立）；铜钱和丹药在进入时自动入账；“略过”跳过选卡。
- **VFX**：大印落下 600ms（2→1，震屏 3dp），战利品胶囊依次弹出（间隔 120ms），3 张卡从牌背翻开（间隔 100ms，每张 300ms）；L 稀有度翻开时加玉色光柱（500ms）。收入时卡牌飞向底栏牌组图标（350ms），牌组数字 +1。

### 8.4 集市
- **层级**：背景 → 店招布幔 → 商人剪影 + 对白 → 铜钱 → 卡牌行 → 货架 → 宝物/丹药/删牌行 → 货架 → 刷新按钮 → 底栏 → 购买确认浮层。
- **缓存**：店招、商人、货架合成一张静态缓存；每个商品格（卡或物品 + 价签）单独缓存，铜钱变化时**只重烘价签**（买不起的价签变红）；已售商品用灰度叠加层。
- **交互**：点商品弹出确认浮层（大图 + 详情 + 购买按钮）；删牌服务打开牌组选择；刷新扣 25 铜钱，或看广告免费刷新（每次进店 1 次，用后按钮置灰）；长按查看详情。
- **VFX**：购买时铜钱从顶部飞向商品（6 枚，350ms），商品飞向牌组或HUD（350ms），铜钱数字滚动；刷新时货架上的商品向下翻牌后换新（400ms）；商人对白在购买后切换（淡入 200ms）。

### 8.5 结算
- **层级**：背景 → 立绘光晕 → 主将立绘 → 竖排大字（大捷/败北）→ 统计面板 → 将魂面板 → 兵书抄录面板（墨值格 + 卡）→ 底栏。
- **缓存**：立绘和大字一起缓存；统计和将魂面板烘焙，数字在滚动期间每帧重绘，滚动结束后烘入缓存；抄录卡逐张缓存，选中状态用叠加层。
- **交互**：
  - 点可抄卡切换选中，墨值格实时预览（待消耗格闪烁）；墨值不足时卡牌抖动并显示需要删除旧卡的入口。
  - “×2”是广告按钮，用于将魂翻倍，或额外抄录 1 张（墨值 ≤2 的卡）。
  - “抄录”确认，“跳过”离开。
- **VFX**：大字逐笔显现（墨笔描绘蒙版，800ms）；4 个统计数字依次滚动（间隔 150ms）；将魂火焰粒子汇聚后数字滚动（800ms）；抄录时卡牌化墨飞入兵书图标（600ms）。失败版：整体去饱和 .6，大字改为“败北”（朱砂），立绘半透明，将魂按 PRD 14.5 折半显示。

### 8.7 营地子状态（`v3/rest.html`，#90 / PR #121）
设计稿 hash：`#temper` 淬炼选牌、`#burn` 焚稿选牌、`#confirm` 词条确认、`#replace` 满词条替换、`#result` 结果面板、`#done` 行动后。坐标均为 390×844 设计坐标；所有遮罩由引擎按真实 W×H 全屏绘制（§4.0，场景只声明 `scrim`）。
- **选牌网格（淬炼 / 焚稿共用）**：5 列，卡 64×92，间距 8，首行 y=150；标题 y≈110（Brush 24 gold）、说明 y≈134（SANS 12 paper3）；取消按钮居中、底栏上方 56。遮罩 `rgba(5,2,1,.88)`。淬炼标题「淬炼·择一」，焚稿标题「焚稿·删一张牌」。
- **淬炼可选规则**：只有词条池为空的牌置灰（α .35），点按 toast「此牌暂无可用词条」。**已满 2 条的牌不置灰**，可点，右上角金签「可替换」；已有词条数以右下 ◆ 表示。

- **满词条替换（#replace）**：同面板，标题「淬炼 · 替换」，说明「此牌已有 2 条词条，选择要替换的一条」；两条旧词条各一个按钮「替换「xx」+效果」，单选高亮；按钮行「淬炼」主（未选旧词条时禁用）/ 「放弃」次，下方小字「放弃也算本次营地已行动」。放弃 = 本次营地已行动，进入 #done。
- **结果面板（#result）**：遮罩 .72；卡牌 big 居中上浮循环（±8px，2.2s）+ 金色光晕（同奖励「收入」高光），下方「已淬炼：xx」（Brush 22 gold），小字「点击任意处关闭」。点任意处关闭进入 #done。焚稿结果同版式，文案「已焚：xx」；疗伤不弹面板，直接体力珠动画 + 进入 #done。
- **行动后（#done）**：已执行的选项保持亮色，其他两项灰（α .4，不可点）；y=584 结果条写一句结果；底栏「确定」置灰，只有「离开」可点（离开 = 回地图）。
- 热区：所有按钮按 §4.0 在屏幕上补足 ≥44×44 CSS px；网格卡牌 64×92 设计坐标已足够。

## 11. WebGL 水墨增强层（取舍与内存见 §12；2D 回退列暂不考虑）
- **启用条件**：WebGL1 可用，`MAX_TEXTURE_SIZE ≥ 4096`，首帧基准测试（200 次绘制）≤8ms，且设备不在低端名单。低端基准机：约 3 年前的千元 Android（约骁龙 680 / Helio G85 档）。测试不通过时整层关闭，回退 Canvas 2D。运行中若连续 3 秒低于 45fps，也自动降级。
- **架构**：Canvas 2D 照常输出主画面；WebGL 层是**叠加的后处理/特效画布**（或由 2D 画布作纹理输入的合成 pass）。每个特效都是独立开关，失败时不影响逻辑。
- **预算**：每帧附加 ≤2 个全屏 pass（与 §10 的覆盖层上限分开计）；shader 只用 mediump；噪声贴图共享。

## 12. 纹理内存 ≤50MB 方案（低端微信，2026-10-12 修订）
> 预算从 150MB（低档 100MB）收紧到 **≤50MB**。原估算约 106MB，需要削减约 60%。暂不考虑 Canvas 2D 回退，按 **WebGL 为主渲染器**计算。计算口径如下：RGBA8 为 4 B/px；ETC2 RGBA 为 1 B/px，ETC2 RGB 为 0.5 B/px；ASTC 6×6 为 0.445 B/px；RGBA4444 和 RGB565 为 2 B/px；R8 为 1 B/px；1MB = 1024² B。

### 12.1 WebGL 水墨特效取舍（13 项 → 7 个 shader）
| 优先级 | 特效（§11 编号） | 处理 | 纹理 |
|---|---|---|---|
| **P0 必留** | #1 墨晕扩散 | 保留；**合并 #6 朱砂溅**（同一 shader，颜色和溅点数作 uniform） | 共享噪声 256² R8 = 64KB |
| P0 | #4 泼墨转场 | 保留 | 笔触 1024×512，EAC R11 0.5 B/px = 256KB |
| P0 | #8 灵光一闪·墨聚 | 保留（核心玩法反馈）；墨云改为**噪声程序化旋转**，不用墨云贴图 | 共享噪声 |
| P0 | #5 墨溶解 | 保留；**合并 #2 渗边**（同一个噪声阈值 shader，受伤时阈值很小即为渗边） | 共享噪声 |
| P1 合并 | #9 书法逐笔描绘 | 保留；**合并 #11 卷轴显影**，统一为“蒙版擦出” shader（输入 SDF/梯度图） | 笔顺 SDF 图集 512² R8 = 256KB（6 个大字 + 卷轴梯度） |

### 12.2 烘焙位图（运行时离屏缓存，RGBA8，不能压缩）
- **降分辨率**：低端机渲染 DPR 上限 2，缓存位图按 **1.5x** 烘焙，绘制时放大到 2x，牌面差异肉眼不可辨。中高端机按 2x 烘焙。
- **按需烘焙**：只烘焙当前在屏的对象，例如手牌、在场敌人、我方主副将、可见徽章。牌组列表等长列表按可见行烘焙。
- **用完释放 + LRU 上限**：

| 缓存类 | 单个尺寸（1.5x，px） | 单个大小 | LRU 上限 | 上限内存 |
|---|---|---|---|---|
| 手牌 72×104dp | 108×156 | 66KB | 10（= PRD 手牌硬上限 10） | 0.66MB |
| 大牌 104×150dp（奖励/集市） | 156×225 | 137KB | 4 | 0.55MB |
| 敌人牌 96×132（Boss 116×160） | 144×198 / 174×240 | 111 / 163KB | 6 | 0.72MB |
| 武将牌主 138×188 + 副 76×104 | 207×282 + 114×156 | 228 + 69KB | 2 套 | 0.59MB |
| 徽章（意图/倒计时/盾/价签） | 48×48 | 9KB | 40 | 0.36MB |
| 详情浮层 180×≤200 | 270×300 | 316KB | 1 | 0.31MB |
| 地图卷轴长图 354×约 700dp | 531×1050 | 2.13MB | 1（离开地图释放） | 2.13MB（与战斗互斥） |
- 离开场景时清空该场景的全部缓存；LRU 超限时淘汰最久未绘制的缓存。
- **战斗峰值**：0.66 + 0.72 + 0.59 + 0.36 + 0.31 = **2.64MB**。手牌 LRU 上限与 PRD 5.4 手牌硬上限 10 一致；任何时刻在屏手牌 ≤10 张，第 11 张直接进弃牌堆，不会产生缓存。

### 12.3 大图：压缩纹理与按场景加载
- **格式选择**（运行时检测 WebGL 扩展）：
  - iOS（A8 及以上，微信 WebGL）：`WEBGL_compressed_texture_astc`，用 **ASTC 6×6**；
  - Android：WebGL2 或 `WEBGL_compressed_texture_etc` 时用 **ETC2**（RGBA 1 B/px，不透明图用 RGB 0.5 B/px），支持 ASTC 的机型优先 ASTC；
  - 都不支持时：带 alpha 的用 **RGBA4444**，不透明的用 **RGB565**，均为 2 B/px。**不回退到 RGBA8**。
  - 资源打包时同时产出 `.astc`、`.ktx(ETC2)`、`.png`（转 4444/565），按设备只下载一种。
- 压缩纹理宽高必须是 4 的倍数（ASTC 6×6 须按 6 对齐填充）；图集统一为 2 的幂。
- 预乘 alpha，禁用 mipmap（2D UI 不需要，可省 33%）。

| `fx`（溅点、碎盾、纸屑、晕影） | 1024² | 常驻 |

### 12.5 2D Canvas 路径（WebGL 关闭）
> WebGL 不可用、或判定为低端机时启用。**不支持压缩纹理，全部按 RGBA8（4 B/px）计算。** 不设 WebGL 特效层，§11 的效果在此路径下全部不做（不再提供 2D 替代）。

**分辨率分级**（相对 2x 源图的缩放）：
| 档 | 内容 | 图集 |

| **2x（全清晰）** | 位图数字 2 套；意图、词条、状态图标（§14 的 32 个 id）；勾玉；虎符；花色点数；“墨”角标；按钮和牌框的**九宫格四角**；书法名（武将名、卡名、按钮字） | 单独一张 **`ui_sharp` 1024²** |

### 12.6 落地约束（追加到 §10）
1. 低端机判定（3 年前千元 Android，或 GPU 内存探测 <2GB）：DPR 上限 2，缓存按 1.5x 烘焙，ping-pong RT 用半分辨率。
2. 任何单张纹理 ≤2048²；禁止在运行时把立绘或背景转成 RGBA8 离屏缓存。
3. 纹理管理器记录每张纹理的字节数，**超过 45MB 时告警**，并先淘汰 LRU 缓存，再卸载非当前场景的图集。
4. 立绘、敌人、选将图集用引用计数，场景退出时 `deleteTexture`。
5. 新增特效前必须先在 12.1 登记，并说明它用哪个现有 shader 或噪声。
