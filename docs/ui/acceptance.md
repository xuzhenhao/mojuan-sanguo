# UI 还原度验收清单（设计 → 工程）

> 对照基准：`public/mockups/v2/b.html`（战斗）和 `public/mockups/v3/*.html`，规格以 [render-spec.md](render-spec.md) 为准，流程以 [flow.md](flow.md) 为准。设备：iPhone 12（dpr 3）、一台千元 Android（dpr 2，低档画质）、一台 16:9 短屏、一台 20:9 长屏。
> mockup 中的 CSS 阴影/滤镜只是示意，工程以烘焙贴图实现，**比对的是最终观感**，不比实现方式。

## 1. 通用容差
| 项 | 容差 |
|---|---|
| 位置/尺寸（390 基准 dp） | 大元素（牌、面板、按钮）±2dp；图标、徽章 ±1dp；文字基线 ±2dp |
| 间距 | ±2dp；同组元素的间距必须一致（目测无差异） |
| 颜色 | 令牌色 ΔE ≤ 3（取色对比 render-spec §1）；渐变端点 ΔE ≤ 5；发光、阴影的强度目测一致 |
| 字体 | 书法字必须是霞鹜文楷，**不能出现系统字体回退**；数字用位图字体；字号 ±1dp |
| 动效时长 | 1x 下 ±10%（或 ±30ms，取较大者）；缓动曲线与令牌一致（目测）；倍速 1.5x/2x 时长按比例缩短 |
| 帧率 | 战斗中动画时中端机 ≥55fps、低端机 ≥30fps；空闲时完全停帧（性能面板 0 draw） |
| 内存 | 低端机纹理峰值 ≤50MB（§12） |
| 触控 | 所有可点元素热区 ≥44×44dp；长按阈值 420ms ±30 |
| 2D 路径清晰度（WebGL 关闭，§12.5） | **仅插画与背景放宽**：背景、卷轴底、卡牌/敌人/奇遇插画（1x）以及立绘（0.75x）允许轻微模糊，不作为缺陷，要求无明显锯齿、无色带、无错位；**不放宽**：数字、图标、勾玉、虎符、花色、墨角标、书法名、九宫格四角必须与 WebGL 路径同样锐利（2x） |
| 安全区 | 交互元素不进入胶囊禁区和 Home 指示条区域；背景铺满物理屏 |

## 2. 全局检查

## 4. 验收流程
1. 工程提交每页时附上同状态截图（390×844 逻辑尺寸，`#resp`/`#detail` 等状态各一张）。
2. 设计用叠图工具做 50% 透明叠加比对，超出容差的项在 PR 上逐条评论（附截图和标注）。
3. 动效用录屏逐帧（60fps）测时长。
4. 低端机跑一遍完整流程（点将 → 地图 → 战斗 → 胜利 → 结算），记录 fps 和内存峰值。
5. 所有项通过后，设计在 PR 上 Approve。
