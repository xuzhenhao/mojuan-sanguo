#### 1.1.1 变更日志

**V0.5.13（2026-10-13）· 测试流程**

**V0.5.12（2026-10-13）· 复活时机补充**

- 4.4 新增第⑤⑥条：敌方出牌到一半时复活，本敌方回合立即结束；正在出手的敌人本步算已用掉、剩余出牌作废；未出手的敌人本步保留不消耗，下一敌方回合所有敌人只出闪，再下一回合先打出保留的那一步，之后接原意图；被「闪」替换掉的那一步不补。复活层不是存档点。实现见 #151。

**V0.5.11（2026-10-13）· 战斗页体力显示**

## 2. 产品概述

### 2.1 一句话定位

**水墨风三国题材的 PVE Roguelike 卡牌微信小游戏**：用三国杀式响应与判定打出策略味，用杀戮尖塔式费用、意图与爬塔打出节奏，用卡厄斯梦境式「战斗中进化 + 局外抄录」打出长期构筑乐趣。

| 维度 | 描述                                                         |

3. **主将 + 副将**：同一武将可当主可当副，组合多变；珠联璧合有彩蛋。
4. **灵光一闪**：战斗中卡牌当场变强，爽感即时。

### 3.1 背景故事（玩家可见文案）

史书本应记载三国风云。不知何时，**墨魇**渗入卷页，篡改人名、颠倒胜负。你是**执笔者**，持笔入卷，以武将之魂为墨，重写被污的篇章。

## 4. 核心循环

### 4.1 局内循环

```
点将（主将 + 副将）→ 第 N 章地图 → 选下一层节点
  → 战斗 / 精英 / 奇遇 / 营地 / 集市 / 宝箱
  →（战斗胜利）灵光一闪检测 → 奖励（铜钱 + 三选一卡牌 [+ 宝物/丹药]）
  → 回到地图 → 章末 Boss → 下一章（H5 首版只有第 1 章）
  → 胜利或失败 → 结算（将魂、兵书抄录）→ 再来一局 / 返回点将
```

### 4.2 局外循环

```
结算获得将魂 + 武将熟练度
  → 可选：兵书抄录本局进化卡
  → 解锁新武将 / 提升天命
  → 开新一局（可带兵书卡入起始构筑）
```

### 4.3 单局时长预算

| 阶段        | 目标时长       |
| ----------- | -------------- |
| 选将        | 30–60 秒       |
| 第一章      | 4–6 分钟       |
| 第二章      | 5–7 分钟       |
| 第三章      | 5–7 分钟       |
| 结算 + 抄录 | 30–90 秒       |
| **合计**    | **15–20 分钟** |

### 4.4 失败与继续

- 主将体力降至 0 且濒死未救回 → 若本局还有复活次数则弹出复活，否则本局失败，进入结算。
- 复活：每局 1 次；回复到 `max(2, ceil(最大体力 × 25%))` 体力（7/8 体力 → 2，9 体力 → 3；V0.5.3 定稿维持），并获得 3 护甲（16.2）。
- 「敌人意图改为闪」的结算（V0.5）：①复活发生在敌方回合中时，本敌方回合**尚未结算的出牌全部取消**；②之后的第一个敌方回合，所有存活敌人的意图替换为 `[闪]`（每人 +1 闪标记，受上限 2 约束），不出杀、不出咒和锦囊；③该回合结束后，各敌人从被替换前的意图继续循环（被替换的那一步不补打）；④意图栏在复活后立即显示新的「闪」意图。⑤**敌方出牌到一半时复活（V0.5.12 · #151）**：复活后本敌方回合立即结束；正在出手的敌人，本步算已用掉，剩余出牌作废，之后从它的下一步意图继续；还没出手的敌人本回合不出牌，但这一步**保留不消耗**——下一敌方回合照②只出闪，再下一回合先打出保留的这一步，再接原意图循环。⑥复活层不是存档点（见 4.4.1 存档/刷新）。微信版通过激励视频；**H5 版没有广告，复活为每局免费 1 次**（V0.5.2 已定）。天命 ≥5 没有复活。
- 任意时刻退出：每次结算完成后自动存档（21.4），下次从当前节点继续；读档不能回退到回合中途。

**敌方反应**（flow.md 第 142 行原文）：

> **复活后（PRD 4.4）**：如果复活发生在敌方回合，本敌方回合立即结束：正在出手那个敌人剩下的出牌作废（只墨化该敌人，意图框化墨 300ms，#157 做出敌方牌面后改为牌面化墨），还没出手的敌人这一步保留、不墨化（见 4.4 第⑤条）；意图栏立即刷新为 `flash_mark` 闪意图（250ms）。下一个敌方回合所有敌人只出闪（各 +1 闪标记，上限 2），之后从被替换前的意图继续循环。

与 4.4 对照：取消剩余出牌 = ①；下一敌方回合全员只出闪、各 +1 闪标记（上限 2）= ②；从被替换前的意图继续、不补打 = ③；意图栏立即刷新 = ④。两处规则一致，flow.md 只补了动画时长。

> **数值来源**：25% 回血比例、下限 2、护甲 3 目前**不在 config/** 中（`config/rules.yaml` 无复活相关键），由数值策划给出；实现时应补进 `config/rules.yaml`（建议 `revive.count` / `revive.hpRatio` / `revive.hpMin` / `revive.armor`），届时以 config 为准并回写本文。

## 5. 战斗系统

### 5.1 战场结构

- **玩家侧**：主将（唯一有体力的单位）+ 副将头像（展示技能，不可被选为目标）。
- **敌人侧**：最多 5 个单位，分**前排 / 后排**两排。
  - 前排最多 3，后排最多 2。
  - 若前排清空，后排自动前移成为前排（动画 0.3s）。
- **竖屏布局**：上敌下己，手牌在底部。

### 5.2 距离与攻击范围

| 规则         | 说明                                         |
| ------------ | -------------------------------------------- |
| 基础攻击范围 | 1（只能打到「距离 ≤1」的目标）               |
| 前排敌人距离 | 对玩家恒为 1                                 |
| 后排敌人距离 | 对玩家为 2（当前排存在时）；前排清空后变为 1 |
| 武器         | 可增加攻击范围（见装备）                     |
| 「无视距离」 | 关键词：可选任意存活敌人                     |
| 己方目标     | 仅主将（治疗/增益）；副将不可被敌方选中      |

敌人攻击玩家时距离恒视为 1（敌人意图不校验距离，简化 AI）。

### 5.3 资源：军令

| 项目           | 数值                                                   |
| -------------- | ------------------------------------------------------ |
| 每回合军令上限 | 3（宝物/技能可改）                                     |
| 回合开始       | 军令回满至上限（不累积未用点，除非有「保留军令」效果） |
| 出牌           | 支付卡牌费用；费用 0 牌可任意打出                      |
| 首局默认       | 无额外军令；靠摸牌与费用规划                           |

- **0 费限 1（V0.4，M4）**：出牌阶段主动打出的 0 费非响应牌，每回合每种（同名）最多打出 1 次。**响应牌（配置 `tags` 含 `response`，如闪、T009 无懈可击）不计入**，只在响应窗口打出，次数受敌方行动和连锁 ≤2 层约束（V0.5.5 明确）。配置校验强制 0 费摸牌牌带 `limit`。

### 5.4 牌堆与手牌

| 规则               | 说明                                                                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 抽牌堆 / 弃牌堆    | 抽空则洗弃牌堆为新抽牌堆（保留随机种子，见技术章）                                                                                                          |
| 回合开始摸牌       | 3 张；**本场战斗第一回合额外 +2**（共 5）                                                                                                                   |
| 手牌跨回合         | **保留**（不强制弃光）                                                                                                                                      |
| 手牌上限           | `max(2, 当前体力)` + 技能修正（如遗计 +2、托孤 +1）；**回合结束时**若超上限，玩家选择弃至上限                                                               |
| 手牌硬上限（V0.5） | 任何时刻手牌最多 **10** 张；超过 10 张时新摸到的牌直接进弃牌堆（提示「手满，弃置」，事件原因 `reason: hand_overflow`），不触发任何「弃置时 / 弃牌后」类效果 |
| 起始手牌           | 战斗开始前不摸；进入第一回合再摸                                                                                                                            |

### 5.5 回合阶段（玩家）

严格顺序状态机：

```
回合开始
  → 触发「回合开始」效果（毒、乐不思蜀类判定、宝物等）
  → 军令回满
  → 摸牌
  → 【出牌阶段】玩家行动（可出牌、可发动主动技、可结束）
  → 回合结束弃牌（若超上限）
  → 触发「回合结束」效果
  → 进入敌方回合
```

**取消「每回合限出一张杀」**：杀仅受军令与手牌限制。

### 5.6 敌方回合

对每个存活敌人按站位顺序（前排左→右，再后排左→右）：

1. 依次打出其**当前意图**中展示的牌（逐张结算，每张【杀】单独进入 5.9.1 响应窗口）。
2. 结算后刷新**下一意图**（按 AI 模式表）。

全部敌方行动完毕 → 玩家下回合。

### 5.7 伤害、护甲、体力

| 概念                     | 规则                                                                                                                                                                                                                                                            |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 体力                     | 主将有最大体力与当前体力；归零进入濒死                                                                                                                                                                                                                          |
| 护甲                     | **回合开始时最多保留 2 点**，超出部分清零（V0.3，防止护甲变成跨回合血池）；受伤先扣护甲再扣体力                                                                                                                                                                 |
| 被动免伤配额（V0.4，M2） | 每个敌方回合，所有**判定类或自动触发的免伤**（护主、八卦阵、仁王盾、藤甲、白银狮子等）合计**最多生效 2 次**；手牌闪（主动响应）、护甲、确定性效果（如的卢）不计入。UI 在护主/防具图标旁显示「☯ 剩余次数」。天命 8 降为 1                                        |
| 敌人护甲上限（V0.5）     | 敌人从第 2 回合起，回合开始时（黄天庇佑等加甲效果结算前）护甲最多保留 2 点（`rules.enemyArmorKeep: 2`），所以张宝护甲最多叠到 3                                                                                                                                 |
| 开场护甲                 | 珠联开场护甲 ≤3；与宝物叠加时开场护甲总上限 4。禁止「每次受伤 −1」类效果，统一写成「每回合首次」                                                                                                                                                                |
| 受到伤害（V0.5.1）       | 只有**实际失去体力**（hpLoss > 0）才算「受到伤害」，触发天策、奸雄、天妒、遗策、绝影、刚烈、挟令反击等。护甲完全吸收、被闪抵消、被护主/八卦阵无效的杀都**不算**。卡面统一写「受到伤害（失去体力）后」。以后若需要「被攻击」口径，另加时机 `hit`，不改 `damaged` |
| 杀基础伤害               | 1（可被酒、技能、进化词条修改）                                                                                                                                                                                                                                 |
| 无攻击力系统             | 任何单位（含敌人）都没有独立攻击力；伤害只来自打出的牌。敌人的【杀】固定 1 点，仅当该牌已灵光一闪进化出对应词条时才改变（如「锋锐」+1、「无影」不可闪、「烈焰」火属性）                                                                                         |
| 伤害来源标记             | 杀 / 锦囊 / 属性 / 体力流失（流失无视护甲）                                                                                                                                                                                                                     |

### 5.8 属性伤害与铁索连环

| 属性 | 来源示例         | 特殊                   |
| ---- | ---------------- | ---------------------- |
| 火   | 火杀、火攻类     | 对「铁索连环」状态传导 |
| 雷   | 雷杀、闪电类     | 对「铁索连环」状态传导 |
| 普通 | 普通杀、多数伤害 | 不传导                 |

**铁索连环**：

- 单位可处于「连环」状态（图标可见）。
- 当连环单位受到火/雷伤害时，伤害结算后对其他连环单位造成**等额属性伤害**（不再二次传导）。
- 锦囊「连环」可横置/重置（见卡表）。

### 5.9 响应窗口

#### 5.9.1 杀 → 闪

1. 玩家或敌人声明「杀」并选定目标。
2. 进入响应窗口：目标可打出「闪」抵消（玩家从手牌；敌人消耗「闪标记」）。
3. 超时 / 放弃 → 结算伤害。
4. 玩家响应时限：默认 **8 秒**（设置可调 5/8/12）；快速模式见 UI 章。

#### 5.9.2 锦囊 → 无懈可击

1. 锦囊声明目标（或无目标）。
2. 响应窗口：可打出「无懈可击」使该锦囊无效。
3. 无懈可被再无懈（MVP：**最多连锁 2 次**，防拖时长）。
4. 敌人无懈：部分精英/Boss 意图或被动带「无懈标记」。

#### 5.9.3 濒死 → 桃 / 技能

1. 体力≤0 进入濒死，暂停其他结算。
2. 可连续用桃/酒（酒仅自己濒死时可当桃）或回血技能，直至体力≥1 或放弃。
3. 无法救回 → 战斗失败。

### 5.10 判定（V0.4：独立天机签筒，M1）

1. 判定牌**不从玩家牌组抽**，而是从独立的「**天机签筒**」抽：52 张标准花色（♠♥♣♦ 各 13 张，A–K），抽空后洗回。
2. 固定概率：P(红) = **50%**，P(♥) = P(♠) = P(♣) = P(♦) = 25%，P(♠2–9) = 8/52 ≈ 15.4%（闪电）。玩家牌组的颜色比例不再影响判定。
3. 按效果判定（如红色生效、非 ♥ 生效），签放回签筒弃签区。
4. 改判：若有效果「可用手牌替换判定签」，在亮签后、结算前插入一次选择（`judge_shown` 时机）。
5. 签筒是成长维度：宝物「改签符」（R31）往签筒加入 2 张 ♥。
6. 判定类免伤受 5.7 被动免伤配额限制。

### 5.11 装备区

主将装备区 4 栏：

| 栏位  | 数量 | 说明                    |
| ----- | ---- | ----------------------- |
| 武器  | 1    | 加攻击范围 / 杀相关效果 |
| 防具  | 1    | 闪避或减伤类            |
| +1 马 | 1    | 他人与你距离 +1（防御） |
| -1 马 | 1    | 你与他人距离 -1（进攻） |

替换：新装备进入时旧装备弃置。敌人可有简化装备（作为意图/被动展示，不完整四栏）。

### 5.12 敌人意图系统

#### 5.12.1 意图 = 敌人本回合要打出的牌

意图不再显示伤害数值，而是直接显示敌人本回合将打出的牌及张数（如 `🗡杀×2`、`🗡杀[锋锐] 🗡杀`、`🛡闪`）。敌人的牌为**虚拟牌**（不进入任何牌堆，不可被获得/弃置）。

| 意图牌        | 图标        | 效果                                                                       |
| ------------- | ----------- | -------------------------------------------------------------------------- |
| 杀            | 刀          | 对玩家造成 1 点伤害；玩家可用闪响应                                        |
| 杀[词条]      | 刀+墨迹角标 | 已灵光一闪进化的杀，按词条结算（锋锐：2 点；无影：不可闪；烈焰：火属性……） |
| 万箭齐发      | 箭雨        | 1 点伤害，不可闪（对应原「重击」类）                                       |
| 闪（备闪）    | 盾          | 获得 1 枚闪标记（取代原「防御 N 护甲」）                                   |
| 减益锦囊 / 咒 | 箭下        | 给玩家 Debuff / 弃牌（如「咒·弃1」）                                       |
| 召唤          | 人+         | 召唤小怪                                                                   |
| 特殊          | ？          | 读条技能、变形态                                                           |

- 一个意图可包含多张牌，按显示顺序结算。
- 敌人护甲**只来自技能/特性**（如开场护甲、被动加甲），不来自意图。
- 意图悬浮/长按提示显示「预估总伤害」= 各张牌伤害之和（供 19.5 致命描边使用）。

**杀的响应**：玩家可对敌人每张杀响应闪；敌人若无「闪标记」则无法闪玩家的杀。

#### 5.12.2 闪标记

- 部分敌人回合开始时获得 0–2 枚闪标记。
- 被杀时自动消耗 1 枚抵消（无需 AI 决策）。
- 标记数在敌人头顶显示。

#### 5.12.3 AI 模式（配置字段）

每个敌兵配置：

```
intentPattern: [["杀"], ["闪"], ["杀","杀"]]  // 每回合打出的牌，循环
cardMods: { "杀+": ["E_S01"] }                  // 已进化的牌（词条见 8.5）
# 或
intentAI: "weighted"
weights: { "杀":40, "杀×2":20, "闪":25, "咒":15 }  // 按意图组合加权
hpBranch: { "below50%": "ENRAGE" }  // 阶段切换
```

MVP 优先用**固定循环 + 低血阶段切换**，加权随机用于少数精英。

### 5.13 战斗胜利 / 失败

- 胜利：场上无存活敌人。
- 失败：主将死亡且未复活。
- 胜利后：触发灵光一闪检测（第 8 章）→ 奖励界面（14.8）。
- **整局胜利（V0.5）**：击败本局最后一章的 Boss（H5 首版 = 第 1 章 Boss 张角）。
- **整局失败**：主将死亡且复活次数用完（4.4）。
- **放弃本局（V0.5.4）**：入口有两个，一是启动时有存档弹出的「继续本局 / 放弃本局」，二是设置浮层里的「放弃本局」。放弃需要**二次确认**（「放弃后本局按失败结算，将魂减半，存档将被删除。确定放弃？」按钮「确定放弃」/「返回」）；确认后按失败进入 P5 结算（将魂按 14.5 失败规则 ×0.5），结算后删除本局存档。
- 版本不一致回滚提示（21.4）是 P2 战斗页的子层，玩家点「继续」后从本场战斗第 1 回合开始。

### 5.14 战斗内可选项

| 选项         | 说明                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 结束回合     | 明确按钮，防误触二次确认（可设置关闭）                                   |
| 查看意图详情 | 点敌人弹出本回合出牌列表、每张牌效果（含进化词条）、预估总伤害、是否可闪 |
| 查看牌堆     | 抽牌堆仅显示剩余张数；弃牌堆可查看列表                                   |
| 自动出闪     | 设置项：被杀时若有闪自动打出                                             |
| 跳过动画     | 设置：战斗动画速度 1x/1.5x/2x                                            |

### 6.7 起始牌组构建规则

每名武将有 `starterDeck[]`（见第 7 章）。通用规则：

- 总张数 **12** 张（V0.4）。
- 红色比例统一 50%；闪类（含可当闪的牌）≤3 张，且 ≤25%。
- 至少含：杀×3–5、闪×2–3、桃×1、其余为专属/势力/通用弱卡。

## 8. 灵光一闪

### 8.1 设计目标

战斗中打出牌时，有概率让**正在结算的那张牌的牌组实例**进化：附加一条词条（三选一）。即时爽感 + 构筑差异。

### 8.2 触发时机

- 监听：玩家**打出并成功结算**的牌（被无懈的锦囊不触发；被闪的杀不触发）。
- 装备牌：装备成功进入装备区时判定。
- 闪：成功抵消杀时判定。

### 8.3 概率与保底

| 项目             | 数值                                                        |
| ---------------- | ----------------------------------------------------------- |
| 基础触发率       | 8%                                                          |
| 每场战斗最多触发 | 2 次                                                        |
| 软保底           | 本场累计打出 12 张未触发 → 下一次必触发（仍受每场上限限制） |
| 章节修正         | 第 2 章 +2%，第 3 章 +3%（仅基础率）                        |
| 宝物可改         | 如「墨灵笔」+5% 等                                          |

伪代码：

```
onCardResolved(card):
  if battleEpiphanyCount >= 2: return
  if roll(rate) or softPity: openEpiphanyUI(card)
```

### 8.4 UI 流程

1. 暂停战斗表现，弹出「灵光一闪」层。
2. 展示当前卡牌 → 三个词条候选（名称+描述）。
3. 玩家点选一条 → 该牌实例写入 `modifiers[]`。
4. 可选（**仅微信版**）：看广告刷新词条一次（第 16 章）；H5 不提供刷新。
5. 关闭后继续战斗。

## 9. 兵书存档

### 9.1 设计目标

把「这一局灵光一闪出来的神卡」有限度带入未来开局，形成长期个性构筑；**不是抽卡**，而是玩出来的收藏。

### 9.2 抄录时机

- 任意一局**胜利或失败结算后**，若本局存在进化过的卡牌实例，进入「兵书抄录」可选界面。
- 可跳过。

### 9.3 墨值与容量

| 项目         | 数值                                  |
| ------------ | ------------------------------------- |
| 初始墨值上限 | 6                                     |
| 提升         | 熟练度、成就、天命通关奖励（最高 12） |
| 抄录消耗     | 按卡稀有度 + 词条稀有度合计           |

**单卡墨值消耗**：

```
cost = base(card.rarity) + sum(mod.rarity)
base: N=1, R=2, E=3, L=4
mod:  N=0, R=1, E=2, L=3
```

例：普通杀 + 锋锐(N) + 穿杨(R) = 1+0+1 = 2 墨值。

### 9.4 兵书栏

- 全局共享一个兵书列表（不限武将），但开局时：
  - 仅可打入**当前主将可用**的卡（专属需匹配主将或副将）。
  - 每局限从兵书**带入 0–2 张**（天命≥3 起可带 3，配置）。
- 带入的卡**加入起始牌组**（可超过默认张数，但若总牌>15，开局强制选择删除至 15）。

### 9.5 替换与删除

- 兵书已满墨值时，抄录需先删除旧卡腾出墨值。
- 可随时在局外「兵书」界面删除（不退将魂）。

### 9.6 平衡约束

| 约束     | 说明                                                                                                            |
| -------- | --------------------------------------------------------------------------------------------------------------- |
| 不可抄录 | 宝物、丹药、临时生成的「消耗」牌                                                                                |
| 弱化     | 抄录卡进入新局时，保留词条，但 **L 级词条在天命 0–1 降为 E 效果**（可选，防碾压）——MVP 可先不做降级，靠墨值限制 |
| 唯一     | 同名同词条组合仅能存 1 份                                                                                       |
| 广告     | 结算时可看广告额外抄录 1 张（仍耗墨值，若不足则仅允许墨值≤2 的卡）                                              |

### 9.7 数据字段

```
BingshuEntry {
  id, cardId, modifiers[], costInk,
  fromHeroId, createdAt, winRateSnapshot
}
```

**可见性**：整张地图（所有节点类型和连线）开局全部可见，**不做迷雾**；战斗节点内的具体敌人组合进入后才揭示。已走过的路径描金，当前可选节点高亮。

### 10.3 路线生成（分支与汇合）

1. 网格 8 层 × 4 列。生成 4 条路线：每条从第 1 层随机一列出发，逐层走向下一层的 列−1 / 列 / 列+1（不越界）。
2. 第 1、2 条路线的起点必须不同列，保证第 1 层至少 2 个入口。
3. **不交叉**：若某一步会与已有连线交叉（A 从 c→c+1 而已有 c+1→c），改为直走。
4. 多条路线经过同一格即为**汇合**；从同一格走向不同格即为**分支**。合并所有路线经过的格子为节点、所有步为连线（去重）。
5. 第 8 层所有节点都连到第 9 层唯一的 Boss 节点。
6. 玩家只能沿连线前进到下一层，不能回头、不能跳层。

### 10.4 节点类型分配

先放固定层，再按权重随机分配其余节点，最后校验约束；校验失败用同一种子流重抽（最多 50 次，仍失败则放宽约束 3）。

固定层：第 1 层全部 BATTLE；第 8 层全部 REST（Boss 前营地）；第 9 层 BOSS。

| 层  | BATTLE | ELITE | EVENT | REST | SHOP | CHEST |
| --- | ------ | ----- | ----- | ---- | ---- | ----- |
| 1   | 100    | 0     | 0     | 0    | 0    | 0     |
| 2–3 | 60     | 0     | 25    | 0    | 5    | 10    |
| 4–5 | 45     | 15    | 15    | 10   | 10   | 5     |
| 6–7 | 35     | 20    | 15    | 10   | 15   | 5     |
| 8   | 0      | 0     | 0     | 100  | 0    | 0     |

约束：

1. 第 4 层之前不出现 ELITE 和 REST。
2. **noConsecutive**：沿一条连线相连的父子节点（第 n 层 → 第 n+1 层）不能同为 ELITE、同为 REST 或同为 SHOP；**包括第 7 层 → 第 8 层固定 REST**，所以与第 8 层相连的第 7 层节点不能是 REST。
3. **distinctSiblings**：同一节点的多个后继节点类型尽量不同；只作用于非固定层（第 2–7 层），第 1 层、第 8 层、Boss 层不检查。
4. 每章至少 1 个 ELITE；**每条起点路线上至少能到达 1 个 SHOP**（生成时校验，V0.5.3）。第 8 层 REST 已保证营地。
5. 不设固定精英层（试过第 6 层固定精英，通关率下降 10–30 个百分点）。

权重与层段已定稿（V0.5.3）。**每局期望（V0.5.5，按路线实测）**：普通战 3.6、精英 0.70、奇遇 1.2、商店 0.76、宝箱 0.48、营地 0.28（非固定层）+ 第 8 层固定营地 1。H5 地图**不加**战后回复：配置 `map.betweenBattleHeal: 0`（游戏默认）；三战制回归模拟用 `sim.baselineBetweenBattleHeal: 1`。数值策划已确认整章模拟里没有战后回复（design-v1 12.2），整章通关率口径不需要修正。

### 10.6 营地（REST）

三选一（H5 首版三项都开放；微信版可沿用「二选一 + 广告第三」，见 16.2）：

1. **疗伤**：回复 `max(2, floor(最大体力 × 0.3))` 体力（8 体力 → 2）。体力已满时选项置灰。
2. **淬炼**：选牌组中一张牌，随机给 1 条 N/R 词条（不占战斗内灵光次数；遵守 8.6 叠加规则和锋锐每牌组 ≤2 张）。无可淬炼牌时选项置灰。
3. **焚稿**：删除牌组 1 张牌（删除后牌组至少 8 张，且至少保留 1 张杀类）。无可删牌时选项置灰。

#### 10.6.1 共用规则（V0.5.5）

- 每进一次营地只做 **一项**；选定并结算后返回地图，不能再选第二项。
- 第 8 层固定营地与随机营地规则相同，无额外加成（宝物 R03「青囊书」的额外回血照常生效）。
- 出口：三项任一完成，或点「离开」→ 回地图 P3。

#### 10.6.2 疗伤

- 公式：`heal = max(2, floor(maxHp × 0.3))`，再加宝物加成（如 R03 +2），不超过当前体力上限。
- 体力已满：选项置灰，文案「体力已满」。

#### 10.6.3 淬炼

- 候选牌：牌组中所有牌；点选一张进入词条生成。
- 词条池：该牌 `category` 对应的 affix 目录中，稀有度为 **N 或 R** 的词条（不含 E/L）。
- 过滤：
  1. 已达该牌实例词条上限（最多 2 条，见 8.6）→ 进入「替换一条或放弃」。
  2. `mutex` / `mutexTags` 与已有词条冲突 → 排除。
  3. 锋锐（E_S01）`maxPerDeck: 2`：牌组中已有 ≥2 张带锋锐的杀时，候选不含 E_S01。
  4. 词条与牌本身效果无意义重复（配置侧）→ 排除。
- 过滤后池空：提示「此牌暂无可用词条」，回到选牌。
- 生成：从过滤后池中均匀随机 1 条（局内 rng）；**一次淬炼只给 1 条，不做三选一**。
- 不占战斗内灵光一闪次数与保底。

#### 10.6.4 焚稿

- 可删条件：删后牌组 ≥8 张，且至少保留 1 张杀类（`category: sha` 或 tag 含杀）。
- UI：列出牌组；不满足条件的牌置灰并显示原因。
- 删除后立即生效，无撤销。

### 14.5 将魂与结算（V0.5）

```
将魂 = 通关章数 × 30 + 精英击杀 × 8 + 战斗胜利场次 × 2 + Boss 击杀 × 40
失败（含主动放弃本局，5.13）：上式按实际进度计算后 ×0.5（向下取整）
天命加成：× (1 + 0.1 × 天命)
微信版：结算可看广告 ×2（16.2）；H5 版没有翻倍
```

实测（V0.5.3）：一局通关约 30 + 0.72×8 + 5.5×2 + 40 ≈ **87** 将魂；败局多在第 4–7 层，约 8–20。公式定稿。

**结算页（P5）显示内容**：

1. 结果：大捷 / 败北，到达的章与层，用时，`runSeed`。
2. 阵容：主将、副将、珠联名。
3. 战报：战斗胜利场次（普通 / 精英 / Boss）、总回合数、造成伤害、承受伤害、最大单回合掉血、灵光一闪次数、复活是否使用。
4. 最终牌组（含词条）、宝物、剩余铜钱。
5. 将魂明细（按上式逐行）与合计；累计将魂。
6. 解锁提示：首次通关解锁天命 1（15.3）；成就（P1）。
7. 兵书抄录入口：本局有进化牌时可进入（第 9 章），可跳过。
8. 按钮：「再来一局」（同主副将，新 `runSeed`，直接进 P3）/「返回点将」（P1）。

### 14.7 价值模型（V0.4）

1 点 = 1 点伤害 = 抵消 1 点伤害。

| 资源            | 价值                           | 依据                                                      |
| --------------- | ------------------------------ | --------------------------------------------------------- |
| 1 军令          | 1.5 点                         | 每回合 3 军令加摸 3 张，产出约 4.5 点                     |
| 1 张手牌        | 1.0 点                         | 平均每张牌产出约 1 点                                     |
| 1 点体力        | 1.5 点                         | 不可再生，还决定手牌上限                                  |
| 1 点护甲        | 0.8 点                         | 回合开始只保留 2 点，有溢出损耗                           |
| 1 点不可闪伤害  | 1.3 点                         | 不能被闪和判定抵消                                        |
| 敌方 1 张杀     | 1 点输入（杀+ 2 点）           | 已定规则                                                  |
| 敌方 1 枚闪标记 | 1.5 点                         | 白吃玩家 1 张杀（1 军令 + 1 牌 ≈ 2.5，乘约 60% 的使用率） |
| 回合持续效果    | 单回合价值 × 6（战斗期望回合） | —                                                         |
| 战斗开始效果    | 单次价值                       | —                                                         |

**定价公式**：净值 = 效果点数 − 1.5 × 费用 − 1.0（占 1 张手牌）。
净值目标：N ≈ −0.5~0，R ≈ 0~+0.5，E ≈ +0.5~+1.0，L ≈ +1.5~+2；武将专属牌比同稀有度再高 0.5（只限一名武将使用）。

武将预算：体力 × 1.5 + 主将技（每回合 1.6 ± 0.2 点 × 6）+ 副将技（每回合 0.5 ± 0.1 × 6），主将合计 ≈ 22 ± 1.5 点。珠联预算每场 2–3 点。

## 21. 技术需求（引擎无关）

### 21.1 架构

```
Presentation（UI/动画）
    ↕ 事件
GameLogic（纯确定性：战斗/地图/随机）
    ↕
Config Tables + RNG(seed)
    ↕
Save / Net / Ads Adapter
```

- **逻辑层禁止读时间/随机无种子 API**。
- 表现层可插值动画，不改变逻辑结果。

### 21.2 确定性 RNG

```
class SeededRNG {
  next(): number        // [0,1)
  shuffle(arr)
  weightedPick(items)
}
streams: map / combat / reward / epiphany 分流，避免一处消耗影响另一处。
```

### 21.3 效果与触发器

建议结构：

```
CardEffect / SkillEffect
Buff { id, stacks, duration, hooks }
Trigger: OnTurnStart, OnPlayCard, OnDamage, OnDying, OnJudge...
Pipeline: 声明 → 响应窗口 → 结算 → 死后触发
```

响应窗口状态机：`IDLE → WAIT_DODGE → WAIT_NULLIFY → RESOLVE`。

### 21.4 断点续玩存档

```
RunSave {
  version, runSeed, chapter, mapState,
  heroMain, heroSub, hp, maxHp, gold,
  deck[], relics[], potions[], bingshuTaken[],
  nodePath[], battleState?(nullable),
  tianming, timestamp
}
```

- **续玩粒度（V0.5，与 engine-design 已决定一致）**：每次结算完成（结算栈清空、进入下一个决策点）自动存档；断线或退出后恢复到**最近一个决策点**（例如刚出完一张牌后），不是回合开始。读档不能回退。若存档的 `configVersion` 与当前配置版本不一致（热更新后），**回滚到当前战斗开始时**：恢复进入本场战斗前的局状态（体力、牌组、铜钱、宝物、丹药、地图路线），用新配置从第 1 回合重新开始本场战斗；不在战斗中则直接用新配置继续。回滚时弹出提示（V0.5.2 已定）：

> 游戏已更新。为保证规则一致，本场战斗将从头开始；进入本场战斗前的进度（体力、牌组、铜钱、地图路线）均已保留。
>
> 按钮：「继续」

- **防 SL**：存档里保存 `rngState`（各随机流 map / combat / reward / epiphany 的当前状态），每次结算后自动存档；读档后随机结果与退出前一致，退出重进不能刷新抽牌、判定、奖励或灵光。
- **配置版本**：存档记录 `configVersion`；局外热更新时，**进行中的局沿用开局时的配置版本**，直到出现上述版本不一致的情况（例如旧配置已不可用）才回滚；新局使用新配置。
- V0.5 补充字段：`rngState`、`configVersion`（V0.5.2）、`battleStartSnapshot`（回滚用，进入战斗时写入）、`mapState { nodes[{id, layer, col, type, encounterId?}], edges[[from,to]], visited[], current }`、`reviveLeft`、`freeRefreshUsed`（H5 每局首次免费刷新）、`shopRemovalsUsed`、`stats { battlesWon, elitesKilled, bossKilled, turns, dmgDealt, dmgTaken, maxTurnLoss, epiphanies }`（供结算页 14.5 使用）。
- 战斗中退出：保存 `battleState` 完整快照（牌堆顺序、手牌、敌人意图索引、Buff）。
- 进战斗节点时先写盘再播动画。
- 旧存档迁移（含战斗中状态的回退规则与提示）：见 [`docs/specs/runstate-migration.md`](specs/runstate-migration.md)（#122）。

### 21.5 配置表（V0.4：YAML，一物一文件）

- 格式：策划编辑 **YAML**（可写 `#` 注释）；**每个武将、技能、卡牌、敌人、词条各一个文件**（宝物、丹药、状态同理），全局规则放 `rules.yaml`，天命放 `ascension.yaml`。
- 目录（建议 `config/`）：`schema/`、`rules.yaml`、`heroes/*.yaml`、`skills/*.yaml`、`cards/{basic,trick,delay,equip,faction,exclusive}/*.yaml`、`enemies/ch{1,2,3}/*.yaml`、`encounters/`、`affixes/*.yaml`、`relics/`、`potions/`、`statuses/`、`ascension.yaml`。
- 构建：`scripts/build-config.ts` 合并为 `dist/config.json` 供运行时加载；小游戏包内不放 YAML 解析器。
- 校验：`npm run config:check` = JSON Schema + 业务校验（引用 id 存在、起始牌组红色 50%、单回合意图 ≤3 张、珠联开场护甲 ≤3、0 费摸牌牌必须有 `limit`），CI 必跑。
- 效果用 DSL 描述：触发时机 `when` + 限次 `limit`（含 `passiveQuota`）+ 条件 `if` + 效果原子 `do`。详见 [design-v1-config.md](proposals/numbers-v1/design-v1-config.md)。
- **分工（V0.5.2）**：地图配置键 `map.*`（10.1、10.4）和 `encounters/*.yaml` 的 `pools` schema（10.5）由研发助手 1 在 P3 开发时编写，PRD 助手评审字段与规则是否一致。
- 图标 id（19.1.2）作为配置中所有 `icon` 字段的**校验枚举**，`npm run config:check` 检查。
- **schema 文件（V0.5.5）**：
  - `config/schema/rules.schema.json`：`map.*`（层数、列数、路线数、权重、固定层、约束、`betweenBattleHeal`）与 `sim.baselineBetweenBattleHeal`。
  - `config/schema/encounter.schema.json`：`pools`（每组 `name` + `enemies`）与规则 `easyBattles: 2`、`noRepeatInPool`。
  - `config/schema/icon.schema.json`（PR #78）：19.1.2 的 45 个图标 id 枚举。
- YAML 1.1 会把 `on/yes/no` 解析成布尔，触发键名统一用 `when`。
- 热更：微信 CDN 分包配置（审版本策略允许前提下）。

### 25.5 快速对照：一局从开到关

1. 大厅点「开局」→ 选天命 → 选主将副将 → 可选带入兵书 0–2 张。
2. 进入第一章地图 → 选节点战斗/事件/…
3. 战斗：摸牌、出牌、响应、敌方意图。
4. 可能灵光一闪 → 奖励三选一。
5. Boss → 第二章 → 第三章。
6. 结算将魂 → 抄录兵书 → 回大厅。
